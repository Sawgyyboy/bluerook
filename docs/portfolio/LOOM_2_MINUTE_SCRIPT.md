# 2-minute Loom script

## Purpose

A fuller portfolio introduction for applications, direct outreach or a buyer who wants to see the connected ecosystem.

## Recording path

`/work/` → `/work/ecommerce-operations/` → `/work/sports-enrollment-operations/` → `/products/` → `/capabilities/managed-operations/` → `/capabilities/system-builder/` → `/technical-portfolio/`.

## Script

**0:00–0:18 — Lobby**

“Hi, I’m Hatim Beid, founder of Bluerook. I design systems around the operation behind the outcome. This lobby starts with fragmented signals, then shows the path that makes each one owned: signal, system, human judgement and completion.”

**0:18–0:42 — Commerce**

“The commerce chapter is a fictional interactive demonstration using a synthetic retailer. It connects storefront state, description review, asset approval, order exceptions, support, CRM and management views. The available reference verifies only a front-end storefront prototype, so the simulated Shopify and operational behavior is disclosed as capability reconstruction, not customer proof.”

**0:42–1:04 — Sports enrollment**

“The sports-enrollment journey is also synthetic. It distinguishes verified anonymized CRM, scoring, booking-capacity, handoff, audit and reporting modules from prototype intake, agent routing, follow-up and correction scenes. A lead can move through qualification and booking, while complaints, payment issues and direct requests for a person stop at a human boundary.”

**1:04–1:25 — Products**

“The product library keeps current state visible. Process to SOP is in local validation and its preview calls no live AI service. Meeting Recap to Slack and the Follow-Up Gap Detector are inactive, credential-free workflow packages; their previews prepare reviewable outputs while delivery and outreach remain disabled. Sports Operations OS is a fictional browser-local demo.”

**1:25–1:43 — Managed operations and builder**

“Managed operations shows the service model with synthetic inbox items, files, meeting actions, exceptions and a founder brief. The System Builder is an available-capability planning aid: it makes triggers, actions, records and human boundaries discussable, but it is not a guaranteed architecture or quote.”

**1:43–2:00 — Technical close**

“Story mode explains the journey, Inspect exposes evidence and system contracts, and Summary keeps the decision concise. The technical dossier shows the working stack and the principle behind it: model the state, surface failure, preserve judgement and leave the next operator a readable handoff. I’d welcome a conversation about where that approach could help.”

## Recording guardrails

- Show each public status label before the interaction.
- Keep the cursor away from booking, email and outbound links.
- Never substitute a client name, result or production claim for a synthetic label.
