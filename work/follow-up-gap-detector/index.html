01 · The workflow itself

Rules you can read.
A refusal you can see.

  1. Six records, none reviewed

    Not because anyone is careless. Because no system was watching. The detector runs on a schedule against the CRM's own fields, and it starts from zero assumptions.

  2. Deterministic checks, not a hunch

    No owner. Overdue. No next action. Rules a founder can read and argue with, applied after validation so unusable input never reaches a verdict.

  3. Context is bounded before review

    Each flag becomes a digest entry a person can decide on. Phone numbers and email addresses are excluded from the analysis context by construction, not by policy.

  4. Failure has a path, and Send stays cut

    A missing column stops the scan, alerts the owner and changes nothing. And the outreach node is disabled on the canvas itself: detection never becomes a message.
